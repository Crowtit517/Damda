# 보류 · 나중에 · 하지 않을 것

> PLAN.md의 하위 문서. 1차 범위 밖의 아이디어와, 일부러 뺀 것을 이유와 함께 모아둔다.

## 나중에 할 것

| 아이디어 | 메모 |
|---|---|
| 플레이스토어 등록 | 공개할 때. 1회 약 25달러, 개인정보처리방침 필요 |
| 매주·매년 반복 (고정 항목) | 1차는 매월만 |
| 예산 설정 | "이번 달 식비 30만 원" 같은 목표와 남은 금액 |
| 가계부 일 평균, 가장 많이 쓴 날 | |
| 기간 선택 미니 달력, 시간 스크롤 선택기 | 원본 달빛달력 부품 이식. 1차는 기기 기본 입력창 사용 |
| 일정 막대 (여러 날 일정을 달력 위 막대로) | 원본 `assignLanes()`, `renderBars()` 이식. 1차는 점으로 표시 |
| 달빛달력 데이터 가져오기 | `moonlight-calendar-*` 키를 읽어 변환 |
| 모바일 밀어서 넘기기 | 캘린더는 월, 할 일·가계부는 하루 |
| 검색 | 전체 할 일·지출·일정 검색 |
| 하루 메모 한 줄 (일기) | |
| 할 일 암호화 선택 기능 | 데이터 형식만 열어둠 |
| 사용자끼리 공유 (가족 가계부 등) | 드라이브 숨김 폴더로는 불가능. 별도 설계 필요 |
| "오늘 할 일 N개 남음" 아침 알림 | 서버 필요 → 서버 없는 원칙과 충돌. 필요성이 커질 때만 재검토 |
| 동기부여 문구 (참고 이미지 하단) | |

## 할 일 기능의 보완 예정 이슈

| 문제 | 보완 방향 |
|---|---|
| 날짜 없는 "언젠가 할 일" | 1차는 미지원. 필요하면 "보관함" 검토 |
| 할 일이 많아 패널이 길어짐 | 완료된 할 일은 "완료 N개"로 접기 |
| 두 기기에서 같은 할 일을 다르게 수정 | 1차는 나중 것이 남음. 문제가 되면 필드 단위 비교 |

## 하지 않을 것

| 항목 | 이유 |
|---|---|
| ❌ 은행·카드·결제 연동 | 보안, 금전 사고, 법적 위험 (data-sync.md 5장) |
| ❌ 홈 화면 위젯 | 만들기 복잡하고 쓸 일이 적음 |
| ❌ 서버 푸시 알림 (배민식) | 서버 필요 |
| ❌ 밀어도 안 지워지는 고정 알림 | 네이티브 앱 전용. 원하지도 않음 |
| ❌ exe 배포 | PWA로 PC와 갤럭시 모두 해결 |
| ❌ Firebase 등 별도 서버 | 비용, 카드 등록, 통로 증가 |
