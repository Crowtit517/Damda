# 데이터 · 동기화 · 보안

> PLAN.md의 하위 문서. 저장 구조, 구글 연동, 알림, 보안, 비용, 위험을 다룬다.

## 1. 저장 구조

```
 [갤럭시 담다 앱]  기기 안 저장 · 알림: 폰 알람 직접 예약        [PC 담다 (PWA)]  기기 안 저장 · 알림: 구글 캘린더
        │  저장 후 1초 안에 올림 · 보일 때 5초마다 확인 · 열 때·돌아올 때 즉시  │
        ▼                                                               ▼
 ┌──────────── 구글 (구글이 운영, 무료) ─────────────┐
 │ 구글 드라이브 (앱 전용 숨김 폴더): 할 일·가계부·카테고리·반복 설정 │
 │ 구글 캘린더: 일정 ◄── 삼성 캘린더·노션 캘린더도 같은 데이터       │
 └────────────────────────────────────────────┘
 ※ 우리가 운영하는 서버 없음. 앱 파일은 GitHub Pages의 정적 파일
```

- **기기 먼저 저장(local-first)**: 입력하면 기기 안에 먼저 저장하고 화면에 바로 반영한 뒤, 뒤에서 구글과 맞춘다. 버튼 반응이 인터넷 속도와 상관없고, 인터넷이 끊겨도 그대로 쓴다.
- **기기 저장소**: 지금은 localStorage(테스트 단계) → Phase 3에서 **IndexedDB**(앱용 데이터베이스)로 옮겨 용량과 안정성을 확보한다.
- **갤럭시 앱**: 지금 코드(HTML·JS)를 그대로 쓰고 얇은 안드로이드 껍데기(예: Capacitor)를 씌운다. 지금은 **APK 직접 설치(무료)**, 플레이스토어는 나중에.
- 브라우저 데이터를 지워도 구글에서 다시 받으면 복구된다. 아직 올라가지 않은 몇 초 분량만 위험하다.
- 암호화는 1차에 넣지 않는다. 보안은 **구글 2단계 인증**에 맡긴다. 나중에 선택 기능으로 넣을 수 있게 데이터 형식만 열어둔다.

## 2. 데이터 모델

기기 안에 `ple-v1` 키로 **하나의 JSON**을 저장한다. 드라이브에 올라가는 파일, 내보내기 파일과 같은 형태다.

```js
{
  version: 1,
  tasks:    { [id]: { id, date: 'YYYY-MM-DD', title, category /* 카테고리 id, 없으면 미분류 */,
                      done, movedTo?, createdAt, updatedAt, deleted } },
  expenses: { [id]: { id, date: 'YYYY-MM-DD', type: 'expense'|'income', category, amount, memo,
                      sample?, createdAt, updatedAt, deleted } },
  recurring: { [id]: { id, type, memo, category, amount /* askAmount면 null */, askAmount,
                       day: 1~31 | 'last', startMonth: 'YYYY-MM', endMonth?, paused,
                       createdAt, updatedAt, deleted } },
  catFolders: { [id]: { id, kind: 'task'|'ledger', name, order, createdAt, updatedAt, deleted } }, /* 화면에서는 '묶음'. 비면 자동 삭제 */
  categories: { [id]: { id, kind: 'task'|'ledger' /* 가계부는 지출·수입 공통 */, name, slot: 0~8 /* 0 = 색 없음 */, folderId?, order /* 폴더 안 순서 */,
                        preset? /* 고정 항목 설정 기억: { type, day, amount, askAmount } */, sample?,
                        createdAt, updatedAt, deleted } },
  taskRules: { [id]: { id, title, category, repeat: { type: 'daily'|'weekdays'|'weekly'|'monthly', days?: [0~6], day?: 1~31|'last' },
                       times: ['아침','저녁'] /* 하루 회차 이름, 1번이면 [''] */, startDate, endDate?, createdAt, updatedAt, deleted } },
  events:   { [id]: { id, title, start, end /* 포함 */, time: 'HH:MM'|'', color,
                      reminders: [{ minutes }] /* Phase 5 */, createdAt, updatedAt, deleted } }
}
```

- 모든 항목에 `updatedAt`, `deleted`를 둔다. 삭제는 `deleted: true` 표시만 한다 (다른 기기에서 부활 방지, 실행 취소 가능).
- `movedTo`: 밀린 할 일을 오늘로 가져오면 원본에 가져간 날짜를 남긴다 (중복 가져오기 방지).
- 카테고리는 처음엔 비어 있고 사용자가 적어둔다. v1(기본 카테고리, 지출/수입 분리) 데이터는 처음 열 때 한 번 옮긴다: 지출·수입 → 가계부 하나로, 안 쓰던 기본 카테고리는 지우고, 예시에만 쓰인 것은 예시 표시. 직접 추가·삭제한다. 삭제하면 그 카테고리의 항목은 `category: null`(미분류)이 된다. 색은 hex가 아니라 팔레트 번호(`slot`)로 저장해 라이트·다크에서 각각 맞는 색을 쓴다.
- **반복 할 일**: 날마다의 할 일을 미리 만들지 않는다. 그날 화면을 열 때 규칙에서 계산해 보여주고, 체크하는 순간 `tasks`에 `id = tr_{규칙id}_{날짜}_{회차}`로 저장한다 (데이터가 쌓이지 않고, 동기화해도 중복 없음). "이 날만 삭제"는 그 id에 삭제 표시, "앞으로 전부"는 규칙의 `endDate`를 전날로.
- **고정 항목 기록**: 날짜가 되면 `expenses`에 `id = r_{규칙id}_{YYYY-MM}`, `recurringId`, `period`를 붙여 만든다. id가 정해져 있으므로 같은 달에 두 번 생기지 않는다 (**기기 간 동기화 후에도 중복 없음**). 사용자가 지우거나 건너뛰면 삭제 표시가 남아 다시 만들지 않는다. 앱을 며칠 안 열었으면 다음에 열 때 밀린 회차를 한꺼번에 기록한다.
- `type`이 없는 옛 지출 기록은 `expense`로 본다. `sample: true`는 예전 예시 데이터 표시로, 앱을 열 때 자동으로 지운다 (예시 기능은 제거됨).
- 달빛달력 원본 필드(`start, end, title, time, color, isTodo, done, createdAt`)와 호환된다. 원본의 `isTodo` 일정은 가져올 때 할 일로 옮긴다.

## 3. 동기화 (Phase 3~5)

| 항목 | 방식 |
|---|---|
| 방식 선택 | ☰ 메뉴에서 이 기기에만 / 자동(아래 기본값) / 절약(열 때·돌아올 때만) / 직접(버튼) |
| 올리기 | 저장 후 **1초 안에** (연달아 바꾸면 1초 동안 모아서 한 번에) |
| 받기 | 앱을 열 때·돌아올 때 **즉시**, 화면에 보이는 동안 **5초마다** 확인 (백그라운드에선 멈춰 배터리 절약) |
| 바뀐 것만 받기 | 캘린더 `syncToken`, 드라이브는 파일 버전을 먼저 비교해 같으면 받지 않음 |
| 앱이 꺼져 있을 때 | 동기화 안 함 → 다음에 열 때 맞춤 (알림은 폰 알람·구글 캘린더가 따로 울림) |
| 기대 속도 | PC에서 입력 → 폰 화면에 **5초 안** (두 기기 모두 화면에 켜져 있을 때) |
| 충돌 | 항목별로 `updatedAt`이 나중인 쪽을 남김 |
| 덮어쓰기 방지 | 저장 전 버전 확인 → 다르면 받아서 합친 뒤 저장 |
| 실패 | 대기열에 두고 다음 접속 때 재시도 |
| 로그인 | Google Identity Services. 토큰은 기기에만 저장하고 약 1시간마다 조용히 갱신 |
| 캘린더 권한 | 캘린더 전체 읽기·쓰기 (기존 일정까지 보기 위함). **읽기를 먼저**(Phase 4), 쓰기는 나중(Phase 5) |

### 구글 캘린더 연동 시 주의
| 항목 | 처리 |
|---|---|
| 삼성 계정, "내 휴대전화"에 저장된 일정 | 보이지 않음 → "구글 계정 일정만 표시" 안내 |
| 반복 일정 | 보기만. 수정은 삼성/구글 캘린더에서 |
| 종일 일정 종료일 | 구글은 "다음 날"로 저장 → 변환 함수 하나로 통일 |
| 색상 | 구글 11색에 맞춤 |
| 중복 생성 | 앱에서 일정 ID를 미리 만들어 재시도해도 1개만 생성 |

## 4. 알림 (Phase 4~5)

| 기기 | 방식 | 꺼져 있어도 | 서버 |
|---|---|---|---|
| **갤럭시 (Phase 5)** | 담다 앱이 **폰 알람 시계(안드로이드)에 직접 예약**. 갤럭시 캘린더와 같은 원리 | ✅ (인터넷 없어도) | 없음 |
| **PC (Phase 4)** | 일정을 구글 캘린더에 저장할 때 알림 설정을 함께 넘김 | ✅ (구글 캘린더가 울림) | 없음 |

- 웹앱(PWA)은 브라우저 보안상 폰 알람을 쓸 수 없다 → 갤럭시는 안드로이드 앱으로 감싸서 해결.
- 할 일(약 먹기 등)도 갤럭시 앱이 직접 알림을 예약한다. "일정으로도 등록"은 필요 없어진다.

- 시간 있는 일정: 10분, 30분, 1시간, 1일 전 (여러 개 가능)
- 종일 일정: "1일 전 오전 9시"처럼 날짜와 시각
- 일반 알림이다. **밀어서 지우면 지워진다.** 앱이 꺼져 있어도 울린다.
- ⚠️ 캘린더 앱이 여러 개면 같은 알림이 2~3번 울릴 수 있다 → 한 앱에서만 알림을 켜도록 안내한다.

## 5. 보안 원칙 · 금융 연동 금지

**이 앱은 직접 입력하는 기록장이다. 은행, 카드, 결제와는 연결하지 않는다.**

| 하지 않는 것 | 이유 |
|---|---|
| 은행 계좌 연동 (오픈뱅킹, 마이데이터) | 토큰 유출 시 계좌 정보 노출. 개인 앱이 감당할 수 없는 책임 |
| 카드사 연동, 카드 내역 자동 불러오기 | 민감한 금융 정보 저장 = 해킹 표적 |
| 결제 기능 (간편결제, PG, 구독) | 금전 피해 직결, 전자금융거래법 등 규제 대상 |
| 문자·알림을 읽어 자동 등록 | 과한 권한 |

- 지출은 **금액, 날짜, 메모**만 저장한다. 입력창 아래에 "카드·계좌번호는 적지 마세요" 안내 줄을 둔다.
- CSP로 허용된 출처만 실행한다. 외부 스크립트는 Phase 3부터 구글 로그인 라이브러리 하나만 쓴다.
- 필수: 구글 계정과 GitHub 계정 2단계 인증
- 자동화가 꼭 필요하면 은행·카드 앱에서 받은 CSV를 **사용자가 직접 가져오는 방식**까지만 허용한다.

## 7. 위험과 대응

| 위험 | 대응 |
|---|---|
| **폰에서 구글 로그인이 자주 풀림** (서버가 없어 토큰이 짧음) | **Phase 2에서 먼저 검증한다.** 잦으면 동기화 설계를 다시 본다 |
| **동기화 버그로 데이터 손실** | 개발 중에는 테스트용 구글 계정을 쓴다. 내보내기를 먼저 만든다. 합치기 로직은 테스트 페이지로 검증한다 |
| 삭제한 항목 부활 | `deleted` 표시 |
| 기기 시계 차이 | 가능하면 구글 서버 시각 기준으로 비교 |
| 테스트 모드에서 약 7일마다 재로그인 | 구글 앱을 "프로덕션"으로 전환 (심사 전에는 경고 화면, 100명까지 사용 가능) |
| 삭제 표시 누적, 파일 증가 | 30일 지난 삭제 표시는 정리. 커지면 연도별 파일로 분할 |

## 8. 구글 연결 준비 (사용자가 한 번, 무료)

1. https://console.cloud.google.com 에서 새 프로젝트 만들기 (예: Damda)
2. "API 및 서비스 → 라이브러리"에서 **Google Drive API** 사용 설정 (캘린더는 Phase 4에서 Google Calendar API)
3. "OAuth 동의 화면": 외부, 앱 이름 "담다", 지원 이메일. 범위에 `drive.appdata`, `userinfo.email`. 테스트 사용자에 본인 계정 추가
4. "사용자 인증 정보 → OAuth 클라이언트 ID" → 웹 애플리케이션. **승인된 자바스크립트 원본**에 `http://localhost:5500` (나중에 GitHub Pages 주소 추가)
5. 받은 클라이언트 ID를 `js/config.js`의 `GOOGLE_CLIENT_ID`에 넣는다 (비밀값 아님)

## 9. 구현 메모 (Phase 3, 10-03)

- `js/sync/google.js`: Google Identity Services 토큰 방식. 권한은 `drive.appdata` + `userinfo.email`만. 토큰은 메모리에만, 약 1시간
- `js/sync/drive.js`: 앱 전용 숨김 폴더의 `damda-data.json` 하나를 찾기·버전 확인·받기·만들기·고치기
- `js/sync/engine.js`: 버전이 바뀌었으면 받아서 합치고(`importData`, 항목별 updatedAt), 올리지 않은 변경이 있으면 올리기 직전 버전을 한 번 더 확인한 뒤 올린다. 방식별 타이밍(auto 1초·5초 / saver 열 때·돌아올 때·떠날 때 / manual 버튼). 로그인 만료 시 "다시 로그인 필요"
- 설정값(테마, 마지막 화면 등 `ple-*` 설정)은 기기마다 따로이고 동기화하지 않는다. 데이터(할 일·가계부·카테고리·반복·일정 캐시)만 맞춘다
- 검증: 가짜 드라이브로 두 기기 상황을 흉내 내 확인 (첫 업로드, 1초 자동 올림, 다른 기기 변경 받기, 동시 수정 둘 다 유지, 삭제 전파, 5초 안 받기 ≈3.3초, 로그인 만료, 연결 끊기 후 기록 유지)
- 남은 일: 기기 저장소 IndexedDB 전환, 실제 구글 계정으로 검증 (로그인 유지 시간)
