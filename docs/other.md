## 2. 서버가 필요 없는 이유 (정리)

- **"구글 클라우드 등록"은 서버가 아니다.** 구글 로그인을 쓰는 모든 앱이 개발할 때 한 번 하는 신청 절차. 사용자는 보지 않는다.
- 데이터는 구글이 운영하는 드라이브·캘린더에 저장되고, 앱이 직접 읽고 쓴다.
- **로그인 느낌**: [구글 계정으로 연결] → 폰·크롬에 있는 계정이 쭉 뜸 → 탭 (폰 설정에 따라 지문) → 처음 한 번만 "허용". 비밀번호 입력 없음.
- **로그인 유지**: PC 웹앱은 약 1시간마다 조용히 갱신(가끔 팝업이 잠깐 깜빡임). 갤럭시 앱은 안드로이드 구글 로그인을 써서 일반 앱처럼 계속 유지. 둘 다 서버 없음.
- 서버가 필요해지는 경우: 가족 공유 가계부, 1초 이내 진짜 실시간, 앱이 꺼져 있어도 오는 맞춤 알림(아침 요약 등).

## 3. 나중에 수익화한다면 (광고·판매)

| 방식 | 방법 | 비고 |
|---|---|---|
| 광고 | AdMob (구글 광고) | 맞춤 광고 동의 화면 필요 |
| 유료 앱 / 앱 안 결제 | 구글 플레이 결제 | 구글이 결제 처리, 수수료 보통 15% |
| 등록비 | 구글 플레이 개발자 계정 | 1회 약 25달러 |

- **"결제 기능 금지" 원칙과 충돌하지 않는다.** 금지한 것은 담다가 은행·카드 정보에 직접 손대는 것. 플레이 결제는 구글이 전부 처리하고 담다는 결과만 받는다.
- 판매 단계에서 필요한 것:
  - **개인정보처리방침** 페이지 (플레이스토어·구글 로그인·광고 모두 필수)
  - **구글 앱 심사**: 사용자 100명을 넘으면 필요. 캘린더 권한은 심사가 까다롭다
  - **사업자 등록, 통신판매업 신고** (국내 유료 판매·광고 수익 시 필요할 수 있음), 세금
- 서버가 없어 **운영자가 사용자 데이터를 보관하지 않는다** → 개인정보 책임이 가볍다 (설계상 장점).

## 4. AI로 만든 앱을 팔아도 되나

| 걱정 | 정리 |
|---|---|
| AI로 만들어서 판매 금지? | 아님. AI 도움으로 만든 앱·서비스는 이미 많이 판매되고 있다 |
| 약관 | Anthropic 약관은 일반적으로 결과물의 사용·상업적 활용을 허용. **판매 전 가입 요금제의 최신 약관 확인** |
| 저작권 | 한국(저작권위원회 안내)·미국(저작권청) 모두 사람의 창작 기여가 없는 AI 산출물은 보호가 어렵다는 입장. **팔 수는 있지만** 코드를 베꼈을 때 막기가 약할 수 있다. 기획·화면 구성·선택과 배치 같은 사람의 결정은 보호 여지 |
| 이름 보호 | **"담다" 상표 출원**이 가장 확실한 보호 (AI와 무관). 출원 전 KIPRIS에서 같은 분야 상표 확인 |
| 남의 것 침해 | 외부 라이브러리 없이 작성. 폰트(Gowun Batang·Dodum)는 상업 사용 가능한 OFL. 판매 전 라이선스 재점검 |
| 플레이스토어·AI 기본법 | AI로 개발했다는 이유의 금지는 없음. AI 관련 규칙은 주로 앱 안에서 AI가 콘텐츠를 만드는 기능에 적용 → 담다는 해당 없음. 시행 세부는 판매 시점에 확인 |
| 진짜 조심할 것 | AI 문제보다 개인정보처리방침, 사업자 등록, 세금 같은 일반 판매 의무 |

- **기록이 증거가 된다**: PLAN.md의 요구사항 목록·결정 기록은 "사람이 무엇을 결정했는지" 보여주는 자료. 계속 남긴다.

## 5. 이 개발 방식은 무엇인가

- **바이브 코딩**(코드를 직접 읽지 않고 결과를 보며 AI에게 말로 고쳐 나감)의 성격이 있지만, 실제로는 그보다 체계적인 **AI 협업 개발 / 에이전틱 코딩**에 가깝다.
  - md로 틀을 먼저 잡고 원칙·범위·로드맵을 정함 → **스펙 주도 개발**
  - 요구사항을 정리하고 상태를 관리 → **기획자·PO(제품 책임자)** 역할
  - "수정 전에 물어봐", "검토 위주로" → 사람이 결정권을 쥔 AI 관리
  - 직접 써보고 피드백 → 사용성 테스트
- **누가 만들었나**: 코드는 AI(Claude)가 작성했고, 무엇을·왜·어떻게 만들지는 사용자가 정했다 (감독과 촬영팀 같은 관계). 소개할 때는 "기획하고 AI와 함께 개발했다"가 정확한 표현.
- 오래 운영하거나 판매하려면 최소한 **구조(어느 파일이 무엇을 하는지)**는 알아두면 좋다 → 필요하면 "담다 설계도"를 비개발자용으로 정리.

## 6. 갤럭시 기본 캘린더와의 관계 (참고)

- 삼성 캘린더는 일정을 **구글 계정·삼성 계정·내 휴대전화** 중 고른 곳에 저장. 담다와 연결되는 건 **구글 계정에 저장한 일정**뿐.
- 갤럭시 캘린더가 꺼져 있어도 알림이 오는 이유: 서버가 아니라 **폰 자체 알람 시계**에 예약하기 때문. 담다 갤럭시 앱도 같은 방식(Phase 5).
- 노션 캘린더가 빠른 이유: 데이터를 옮기는 게 아니라 같은 구글 캘린더를 보여주기 때문 (대신 노션 서버에 권한을 맡김).

## 7. PC 앱 만들기·나눠 주기 (10-05)

- 코드: `desktop/` (Electron). 웹 담다는 그대로 npm 없이, 이 폴더만 `npm install`
  - 개발: `cd desktop` → `npm install` → `npm run dev` (담다 폴더를 localhost:5500으로 띄워서 연다)
  - 설치 파일 만들기: `npm run build` → `desktop/dist/Damda-Setup.exe` (약 106MB). 한 번 실행하면 바로 설치되고(`AppData\Local\Programs`), 바탕화면·시작 메뉴에 **"담다" 바로가기**만 생긴다(.exe가 보이지 않음). 지우기는 Windows 설정 → 앱. 만든 파일은 git에 올리지 않는다
- **PC 앱 구글 로그인 설정** (한 번, 사용자가 직접): 구글 클라우드 콘솔 → 사용자 인증 정보 → OAuth 클라이언트 ID 만들기 → 유형 **데스크톱 앱** → JSON 다운로드 → 이름을 `oauth.local.json`으로 바꿔 `desktop/`에 넣고 `npm run build`. git에는 올리지 않는다(.gitignore). 구글은 데스크톱 앱의 보안 비밀은 비밀로 보지 않고 앱 안에 넣어 쓰라고 안내한다 → 설치 파일 안에 들어간다
- 서명하지 않은 exe라 처음 실행 때 Windows가 "알 수 없는 게시자" 경고를 띄운다 → [추가 정보] → [실행]. 무료 범위에서는 그대로 둔다
- 다른 사람에게는 설치 파일 하나만 주면 된다 (화면은 공개 사이트에서 받으므로, 사이트를 고치면 exe를 다시 만들지 않아도 최신)
- 시작 화면: PC 앱은 `desktop/splash.html`, 폰(홈 화면 앱)은 `js/ui/bootSplash.js`. 처음 만든 시험판은 `test/splash-demo/`(`시작 화면 보기.bat`)
- 시험: `test/pc_qa.mjs`(PC 전체 68개, 개발 모드에서), `test/mobile_splash.mjs`(폰 시작 화면), `test/web_regress.mjs`(폰·웹 화면이 그대로인지)
- `test/`: 개발 중 쓴 시험 스크립트(가짜 구글 서버로 검증)·화면 사진·PC 시험판과 그 데이터. **이 PC에만 두고 git에는 올리지 않는다**(10-05). 앱은 쓰지 않는다

## 8. 갤럭시 앱 만들기·나눠 주기 (10-05)

- 코드: `mobile/` (Capacitor 6). 시험용: `cd mobile` → `npm install` → `npx cap sync android` → `cd android` → `gradlew assembleDebug` (JAVA_HOME = 안드로이드 스튜디오의 jbr) → `app/build/outputs/apk/debug/app-debug.apk`
- **정식(나눠 줄) APK**: `mobile/release.cmd` → `mobile/dist/Damda-Galaxy.apk`. 서명할 때 비밀번호를 물어본다. 처음 한 번만 `release.cmd key`로 서명 열쇠를 만든다(`%USERPROFILE%\damda-keys\damda-release.jks`, 레포 밖). **열쇠 파일과 비밀번호는 USB·개인 클라우드에 백업**(잃어버리면 같은 앱으로 업데이트할 수 없음). 안드로이드 부분을 고쳐 다시 낼 때는 `android/app/build.gradle`의 versionCode를 1 올린다
- 구글 로그인 설정(한 번, 사용자): 콘솔 → OAuth 클라이언트 ID → 유형 **Android** → 패키지 `io.github.crowtit517.damda` + 서명 SHA-1. 시험 서명 지문(개발용)과 정식 서명 지문(나눠 주는 APK)을 각각 등록한다(Android 클라이언트 2개)
- 설치: 시험할 땐 개발자 옵션 → USB 디버깅 + `adb install`. 나눠 줄 땐 APK 파일을 GitHub Releases에 올리고, 받는 사람은 내려받아 설치("출처를 알 수 없는 앱" 허용 한 번). 개발자 모드는 필요 없음
- 시험 서명 앱에서 정식 서명 앱으로 바꿀 땐 서명이 달라 한 번 지우고 설치한다(기록은 구글 드라이브에서 다시 불러옴)
- 처음 열 때 "알림 허용"을 묻는다. 정확한 알람은 캘린더 앱 용도라 자동 허용
